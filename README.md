# Fake News API

Асинхронный сервис проекта «Классификатор фейковых новостей с мониторингом дрифта тематик».
Первая домашняя работа содержит служебное API, PostgreSQL, тесты и публикацию Docker-образа.
Обучение модели и MLflow относятся к следующему этапу.

## Быстрый запуск

Нужны Docker с Compose и запущенный Docker daemon. На Mac с Colima: `colima start`.
Все команды выполняются из корня репозитория.

```bash
docker compose up --build -d
docker compose ps
docker compose logs -f app
```

[Swagger](http://127.0.0.1:8001/docs). PostgreSQL доступен на компьютере через `127.0.0.1:5433`,
в сети Compose — через `db:5432`. Приложение ждёт готовности БД; у обоих сервисов есть healthcheck.
Учебные настройки по умолчанию показаны в `env.example`; для своих значений создай `.env`
по этому примеру. Существующий `.env` перезаписывать не требуется.

| Метод и путь | Назначение |
| --- | --- |
| `GET /healthz` | Быстрая проверка процесса, без обращения к БД; служебный путь не зависит от версии API |
| `GET /api/v1/version` | Версия приложения из `pyproject.toml`, а не номер API `v1` |
| `GET /api/v1/health` | Реальный запрос к PostgreSQL, его версия и время ответа в миллисекундах; при ошибке/таймауте — 503 |

Остановить стенд: `docker compose down`. Именованный volume сохраняет данные PostgreSQL.
`docker compose down -v` удаляет этот volume с данными.
Оба сервиса ограничены одним CPU и 512 MiB памяти. Docker хранит до трёх файлов логов по 10 MB на контейнер.

## Запуск Python на компьютере

Нужны uv и Python 3.12. Создай `.env` по `env.example` и запусти:

```bash
uv sync --locked --group web --group dev
docker compose up -d db
uv run --locked --env-file .env --group web uvicorn app.main:app --reload --port 8002 --no-access-log
```

Локальная [документация API](http://127.0.0.1:8002/docs). Если порт занят, укажи другой через `--port`.
`DATABASE_URL` внутри контейнера Compose формируется отдельно, с адресом `db:5432`.
Если меняешь параметры пользователя/БД на компьютере, согласуй с ними локальный `DATABASE_URL`.
Изменение переменных `POSTGRES_*` не меняет пользователей уже инициализированного volume автоматически.

## Проверки

```bash
uv run pre-commit install
uv run pre-commit run --all-files
uv run --locked --env-file .env --group web --group dev python -m pytest --cov=app --cov-report=term-missing
```

Тестам успешного `/health` нужна работающая PostgreSQL. Отдельно проверяются недоступность и таймаут БД,
ответ 500 при неожиданной ошибке и содержимое логов. Процент покрытия строк не заменяет проверку сценариев.
Ruff проверяет базовые ошибки Python (`E4/E7/E9`, `F`), импорты (`I`) и вероятные ошибки (`B`).
Форматтер использует двойные кавычки, табы и целевую длину строки 88 символов.

## Логи

События приложения выводятся в stdout как JSON: время UTC, уровень, модуль и `event`.
Записи запросов содержат `method`, `path`, `status_code`, `duration_ms`;
ошибки БД — `component` и `error_type`; запуск и остановка — `version`.
Строки подключения, тексты исключений, тела, заголовки и query-параметры в эти события не включаются.
Стандартный access-log Uvicorn в образе отключён, чтобы не дублировать запросы и не выводить query-параметры.
Служебные сообщения запуска Uvicorn могут иметь его стандартный текстовый формат.
Уровень приложения задаётся `LOG_LEVEL` (по умолчанию `INFO`).

## CI/CD и версии

CI проверяет push в ветки и pull request. CD запускается по Git-тегам `v*`, сначала вызывает тот же CI
для отмеченного коммита, затем сверяет версию и публикует образ в GHCR.
Теги обозначают намеренный выпуск: промежуточные коммиты проверяются, но не публикуются как релизы.

Каждый образ получает тег версии и `sha-<полный SHA коммита>`: первый удобен человеку, второй связывает
сборку с исходниками. `pyproject.toml` — источник версии для API и CD; Git-тег должен равняться `v<version>`.
Для локальной сборки `APP_VERSION` в Compose/`env.example` следует согласовывать с этой версией.
Подробности и порядок выпуска — в [docs/ci-cd.md](docs/ci-cd.md).

Опубликованный образ: `ghcr.io/klopsiq/mlops-fake-news:<version>`. Для проверки конкретного выпуска:

```bash
docker pull ghcr.io/klopsiq/mlops-fake-news:0.1.3
```

Структура: `app/` — приложение, `tests/` — проверки, `.github/workflows/` — CI/CD, `docs/` — документация.
