# Проверки и выпуск образов

## Условия запуска

CI запускается при push в любую ветку и при pull request. Он устанавливает зависимости из `uv.lock`,
поднимает PostgreSQL service, проверяет Ruff/форматирование и запускает pytest с coverage.
Отчёт `coverage.xml` сохраняется как артефакт `coverage-report`.

CD запускается при отправке Git-тега `v*`. Задание `checks` вызывает CI из того же коммита;
`publish` зависит от него через `needs`. Ошибка проверок или несовпадение версии останавливает публикацию.
Так перед публикацией проверяются именно выпускаемые исходники, а не случайный предыдущий запуск ветки.

Тег — явное решение выпустить версию. Это отделяет выпуск от обычных промежуточных push и позволяет
позже найти соответствующий коммит. Шаблон `v*` — фильтр запуска, а не валидатор формата SemVer:
точное соответствие `v<project.version>` проверяет Python-шаг CD.

## Где задаётся версия

`[project].version` в `pyproject.toml` используется API и CD. В `uv.lock` записана версия самого проекта,
поэтому после изменения версии выполняется `uv lock`. Локальный тег образа задаётся переменной
`APP_VERSION` в Compose с версией текущего выпуска по умолчанию; при выпуске обновляется и `env.example`.

Например: версия приложения `0.1.3`, Git-тег `v0.1.3`, образ `ghcr.io/klopsiq/mlops-fake-news:0.1.3`.
Дополнительно создаётся `sha-<полный SHA>` для поиска исходников конкретной сборки.
Имена тегов являются метками: для получения ровно того же содержимого реестр также предоставляет digest SHA256.

## Порядок выпуска

1. Изменить код, версию проекта, версию по умолчанию в Compose и `APP_VERSION` в примере окружения.
2. Выполнить `uv lock`, тесты и pre-commit; проверить локальную Docker-сборку и три ручки.
3. Добавить выбранные файлы через `git add`, создать коммит. Установленный Git-хук проверит его содержимое;
   если хук исправил файлы, просмотреть изменения и повторно добавить их в индекс.
4. Отправить ветку, дождаться CI, поставить тег на готовый коммит и отправить его:

```bash
git push origin main
git tag -a v0.1.3 -m "Release 0.1.3"
git push origin v0.1.3
```

Для следующего выпуска используется новый номер и новый тег. Уже опубликованные теги не передвигаются.
Re-run старого запуска проверяет старый коммит и не подхватывает новые исправления из ветки.

## Авторизация и проверка результата

GHCR выбран потому, что находится рядом с репозиторием и поддерживает публикацию через автоматически
выданный `GITHUB_TOKEN`. Право `packages: write` выдано только заданию публикации; тестам достаточно чтения.
Образ собирается для `linux/amd64` и `linux/arm64`.

Во вкладке Actions должны завершиться `checks` и `publish`. В Packages должны появиться оба тега.
Проверь скачивание образа, ответ `/api/v1/version`, подключение к PostgreSQL и логи запуска/остановки.
Сам по себе успешный `docker push` ещё не проверяет работоспособность приложения.
