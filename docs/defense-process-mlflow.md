# Репетиция защиты: POST /process, MLflow и переключение модели

Эта инструкция объясняет, что выполнить, что показать и как рассказать об устройстве проекта на защите.

**Статус проверки:** `/process` и загрузка модели через alias реализованы в коде. Живой ответ API и содержимое Registry при подготовке инструкции не проверены: из среды ассистента не удалось подключиться к локальным сервисам. Версии `1` и `2`, а также примеры ответов ниже — иллюстрации. На защите показывай реальные значения. Наличие кода само по себе не подтверждает готовность всей системы.

## 1. Основные сущности MLflow

| Сущность | Что это | Пример в проекте |
| --- | --- | --- |
| Experiment | Объединяет связанные запуски | `fake-news-hw3` |
| Run | Один запуск обучения или оценки | Обучение `baseline-v1` |
| Parameter | Настройка запуска | `C=1.0`, `ngram_range` |
| Metric | Измеренный результат | `val_f1_macro`, `fit_seconds` |
| Artifact | Сохранённый файл | Матрица ошибок, JSON-отчёт |
| Dataset input | Запись об использованных данных и их роли | Train с контекстом `training` |
| Logged model | Сохранённая модель с описанием формата и окружения | Обученный sklearn Pipeline |
| Registered model | Именованная модель, объединяющая версии | `fake-news-classifier` |
| Model version | Конкретная зарегистрированная версия | `1`, `2` |
| Alias | Переназначаемое имя версии | `champion → 2` |

Связи между сущностями:

```text
Experiment
└── Run обучения
    ├── Параметры, метрики, dataset inputs
    ├── Артефакты: отчёты, матрица ошибок, исходники
    └── Logged model
        └── Регистрация → версия в fake-news-classifier
                         ↑
                    alias champion
                         ↓
                  загрузка при старте API
                         ↓
                     POST /process
```

Один experiment содержит много runs. Run может сохранить несколько моделей. Регистрация выбранной модели создаёт версию в Registry. Alias позволяет выбирать версию по постоянному имени. См. [официальную документацию Model Registry](https://mlflow.org/docs/latest/ml/model-registry/workflow/) и [MLflow Tracking](https://mlflow.org/docs/latest/ml/tracking/).

**Как сказать на защите:**

> Tracking хранит историю экспериментов: данные, настройки, метрики и артефакты. Registry хранит зарегистрированные версии моделей. Alias champion указывает на версию, которую приложение должно загрузить при следующем запуске.

## 2. Подготовка демонстрации

Нужны работающий MLflow, две зарегистрированные совместимые версии и alias `champion`.

Все команды выполняй из корня проекта. Переменная `MLFLOW_TRACKING_URI` действует в текущем терминале; в новом терминале задай её повторно.

```bash
export MLFLOW_TRACKING_URI=http://127.0.0.1:5000

docker compose up -d --build mlflow
```

Дождись готовности сервера:

```bash
docker compose ps
curl -fsS http://127.0.0.1:5000/health
```

Посмотри реальные версии и текущий alias:

```bash
uv run --group ml python - <<'PY'
import mlflow
from mlflow import MlflowClient

mlflow.set_tracking_uri("http://127.0.0.1:5000")
client = MlflowClient()
name = "fake-news-classifier"

for version in client.search_model_versions(f"name='{name}'"):
    print(
        f"version={version.version}",
        f"run_id={version.run_id}",
        f"aliases={version.aliases}",
    )

champion = client.get_model_version_by_alias(name, "champion")
print("Текущий champion:", champion.version)
PY
```

- `version` — номер версии модели.
- `run_id` — идентификатор исходного запуска.
- `aliases` — назначенные этой версии имена.

Если нужных версий или alias нет, подготовка ещё не завершена. Обученную модель регистрируют командой ниже, заменив URI на **реальный `model_uri` из результата обучения**:

```bash
uv run --group ml python -m ml.register \
  --model-uri 'models:/РЕАЛЬНЫЙ_MODEL_ID' \
  --alias champion
```

Для второго обученного кандидата повторяют регистрацию с его URI без `--alias champion`. Само обучение модели ещё не означает её регистрацию. Повторная регистрация создаёт очередную версию; номера нужно проверять в Registry.

## 3. Демонстрация POST /process

Запусти приложение:

```bash
docker compose up -d --build db app
docker compose logs --tail=50 app
```

В логах ищи сообщение с фактическим номером:

```text
Загружена модель fake-news-classifier версии ...
```

Дождись завершения запуска и отправь запрос:

```bash
curl -i -X POST http://127.0.0.1:8001/process \
  -H 'Content-Type: application/json' \
  -d '{"text":"The city council approved a new transport budget on Tuesday."}'
```

Иллюстрация формы ответа — **не фактически полученный результат**:

```json
{
  "label": "real",
  "model_name": "fake-news-classifier",
  "model_version": "1"
}
```

**Как объяснить:**

> Я передаю текст в JSON. Приложение вызывает predict у загруженного Pipeline и возвращает класс вместе с именем и точной версией модели. В этом примере предсказание сделала версия 1.

Реальный класс может оказаться другим. Этот запрос демонстрирует выполнение inference; правильность классификации отдельного текста требует подтверждённой разметки.

**Используемую версию определяем по `model_version` в ответе `/process`, дополнительно — по логу загрузки.**

`GET /api/v1/version` возвращает версию приложения из `pyproject.toml`, а не версию модели.

Альтернативно запрос можно выполнить через [Swagger UI](http://127.0.0.1:8001/docs): открыть `POST /process`, нажать `Try it out`, ввести JSON с полем `text`, нажать `Execute`.

## 4. Что происходит внутри приложения

В [app/model.py](../app/model.py) выполняются два действия:

```python
version = MlflowClient().get_model_version_by_alias(name, alias)

model = mlflow.sklearn.load_model(f"models:/{name}/{version.version}")
```

Сначала приложение узнаёт, на какую версию указывает `champion`. Затем загружает модель по конкретному номеру. Поэтому API возвращает номер именно загруженной модели, даже если alias переназначат во время загрузки.

В [app/db.py](../app/db.py) загрузка вызывается в `lifespan` при старте процесса. Модель, её имя и номер сохраняются в `app.state`.

В [app/routes.py](../app/routes.py) обработчик использует:

```python
request.app.state.model.predict([payload.text])
```

Синхронный `predict` выполняется через `run_in_threadpool`, чтобы не запускать его непосредственно в event loop.

**Как объяснить:**

> Модель загружается один раз при старте процесса. Каждый запрос использует уже загруженный объект. Для основных обучаемых вариантов Pipeline включает TF-IDF и LogisticRegression, поэтому обработка текста и классификатор сохраняются вместе.

Настройки в [docker-compose.yml](../docker-compose.yml):

```yaml
MLFLOW_TRACKING_URI: http://mlflow:5000
MODEL_NAME: fake-news-classifier
MODEL_ALIAS: champion
```

На компьютере используется `http://127.0.0.1:5000`, а внутри Docker-сети — `http://mlflow:5000`. Имя `mlflow` — имя сервиса Compose.

## 5. Переключение champion на другую версию

Допустим, сейчас приложение использует версию `1`, а версия `2` существует в Registry и совместима с приложением. Подставляй реальные номера из шага 2.

### Шаг 1. Зафиксируй исходную версию

Выполни `/process` и сохрани значение `model_version` для возможного отката. Также проверь текущий `champion` командой из шага 2: до переключения значения должны совпадать, если приложение запущено после последнего изменения alias.

### Шаг 2. Переназначь alias

```bash
uv run --group ml python -m ml.register \
  --model-name fake-news-classifier \
  --version 2 \
  --alias champion
```

Вместо `2` укажи выбранную существующую версию.

Команда использует [ml/register.py](../ml/register.py). С аргументом `--version` она назначает alias существующей версии, без повторной регистрации. Внутри вызывается:

```python
client.set_registered_model_alias(
	name="fake-news-classifier",
	alias="champion",
	version="2",
)
```

Повторно выполни команду проверки Registry из шага 2, чтобы подтвердить новое значение `champion`.

### Шаг 3. Покажи старую версию до перезапуска

```bash
curl -sS http://127.0.0.1:8001/process \
  -H 'Content-Type: application/json' \
  -d '{"text":"The city council approved a new transport budget on Tuesday."}'
```

API должен по-прежнему вернуть прежний номер — в нашем примере `"1"`.

**Как объяснить:**

> В Registry champion уже указывает на версию 2, но работающий процесс держит версию 1 в памяти. В этом проекте обновление выполняется при перезапуске.

### Шаг 4. Перезапусти приложение

```bash
docker compose restart app
docker compose logs --tail=50 app
```

Дождись сообщения о загрузке новой версии и завершения старта приложения. Повтори запрос из шага 3. Теперь ожидаемый номер — `"2"`.

| Момент | Alias в Registry | Версия в ответе API |
| --- | --- | --- |
| До переключения | 1 | 1 |
| После переключения, до restart | 2 | 1 |
| После restart | 2 | 2 |

Предсказанный класс может остаться таким же. **Доказательство переключения — новый `model_version` и соответствующий лог загрузки.**

Для этого сценария не нужно менять inference-код, пересобирать образ или перезапускать MLflow. Требуется переназначить alias и перезапустить приложение.

### Шаг 5. При необходимости выполни откат

```bash
uv run --group ml python -m ml.register \
  --version 1 \
  --alias champion

docker compose restart app
```

Вместо `1` используй сохранённый исходный номер. После старта проверь `/process` ещё раз.

## 6. Как показать происхождение модели

Открой [MLflow UI](http://127.0.0.1:5000), найди зарегистрированную модель `fake-news-classifier`, нужную версию и связанный исходный run. Названия разделов интерфейса могут отличаться между версиями MLflow.

В run покажи:

- параметры обучения;
- validation-метрики;
- входные datasets;
- матрицу ошибок и отчёт;
- сохранённую модель.

Код проекта также логирует Git commit, признак незакоммиченных изменений, исходники и manifest разбиения данных.

**Как объяснить:**

> От ответа API я могу перейти к версии в Registry, от неё — к исходному run и посмотреть, с какими настройками и данными модель обучалась и какие результаты получила.

В текущем Compose метаданные MLflow сохраняются в PostgreSQL сервиса `mlflow-db`, а файлы артефактов — в volume `mlflow_artifacts`. Сервис `db` — отдельная PostgreSQL для приложения.

## 7. Ответы на вероятные вопросы

**Почему не загружать просто последнюю версию?**

Последняя зарегистрированная версия может быть экспериментальной или хуже предыдущей. `champion` обозначает явно выбранную версию. Само имя alias не доказывает качество: выбор нужно обосновать реальными метриками.

**Смена alias переобучает модель?**

Нет. Она меняет указатель на уже зарегистрированную версию. Исходные результаты run и файлы модели от этого не меняются.

**Почему inference-код не меняется?**

Он читает постоянные имя модели и alias из конфигурации. Выбор конкретной версии хранится в Registry.

**Любую модель можно так подставить?**

Нужна совместимость с контрактом приложения: список текстов на входе, метод `predict` и классы `0=real`, `1=fake`. Текущий загрузчик проверяет набор классов, но эта проверка не гарантирует всю совместимость или правильность смыслового mapping. Нужные библиотеки также должны быть доступны в окружении API.

**Что будет, если alias отсутствует или MLflow недоступен при старте?**

Загрузка завершится ошибкой и приложение не стартует. Запасная модель в текущем коде не предусмотрена.

**Если MLflow станет недоступен после успешного старта?**

Обработчик `/process` использует уже загруженную модель и при каждом запросе в Registry не обращается. При следующем старте доступ к MLflow снова понадобится.

**Почему разные версии дали один класс?**

Разные модели могут одинаково классифицировать конкретный текст. Факт переключения определяется по номеру загруженной версии, а не по обязательному изменению класса.

**Проверяет ли модель истинность новости?**

Она классифицирует текст по закономерностям обучающего корпуса. Это не проверка фактов по независимым источникам. Качество на новых источниках, другом языке или другом периоде нужно измерять отдельно.

**Что означают source, digest и lineage?**

`source` — источник данных: в нашем случае URL исходного CSV WELFake. `digest` — отпечаток dataset в MLflow; его нельзя автоматически считать полным SHA-256 исходного файла. `lineage` — цепочка происхождения: CSV → очистка и split → training run → logged model → Registry version → API. Очистку и состав split мы дополнительно фиксируем manifest, SHA-256 и снимком кода. Сам `log_input` не копирует весь CSV в MLflow.

**Где физически находятся данные MLflow?**

Параметры, метрики, связи и Registry находятся в Backend Store — PostgreSQL `mlflow-db`. Файлы Pipeline, картинки, отчёты и исходники находятся в Artifact Store — volume `mlflow_artifacts`, смонтированном в `/mlartifacts` сервера. Клиенты получают артефакты через MLflow по HTTP. Исходный датасет и split находятся в локальной папке `data`, а не целиком в Dataset Tracking.

**Чем `models:/m-...` отличается от `models:/fake-news-classifier/2`?**

Первый URI в MLflow 3 указывает на logged model по её ID. Второй указывает на зарегистрированную версию по имени и номеру. `models:/fake-news-classifier@champion` использует alias. Один только logged model ID ещё не означает регистрацию в Registry.

**Чем signature отличается от input example?**

Signature описывает форму и тип входа/выхода; input example — конкретные входные данные для проверки и пояснения. Для TF-IDF мы сохраняем tensor signature одномерного массива строк. Pyfunc использует эту схему для проверки входа; native sklearn loader не заменяет валидацию нашего HTTP-запроса. Поэтому API отдельно проверяет поле `text` через Pydantic.

**Почему в async endpoint используется threadpool?**

sklearn `predict` — синхронная операция. Если вызвать её прямо внутри `async def`, она будет выполняться в event loop. `run_in_threadpool` переносит вызов в рабочий поток; это не делает CPU-вычисления бесплатными и не гарантирует ускорение модели.

**Как выбрана модель?**

Сначала фиксируем train/validation/test. Обучаем только на train, выбираем по `val_f1_macro`, затем один раз измеряем выбранную версию на test. Macro-F1 даёт одинаковый вес двум классам. Дополнительно смотрим precision/recall для fake и время. Конкретные числа и причина выбора записаны в [отчёте](hw3-results.md).

**Почему TF-IDF находится внутри Pipeline?**

Словарь и веса TF-IDF обучаются только на train. Они сохраняются вместе с классификатором, поэтому на inference используются те же преобразования. Если построить словарь по всему корпусу до split, validation/test начнут влиять на обучение preprocessing.

**Почему есть несоответствие описания WELFake и mapping проекта?**

Описание Zenodo говорит `0=fake`, но числа классов и почти все тексты с Reuters в начале поддерживают обратное соглашение. В проекте явно принято исходное `1=fake`, противоречие и фактические счётчики сохранены в [data/README.md](../data/README.md) и [аудите](../data/label-audit.json). Это обоснованная интерпретация корпуса, а не независимая проверка фактов по каждой новости.

## 8. Если демонстрация не работает

| Симптом | Что проверить |
| --- | --- |
| Не открывается MLflow | `docker compose ps`, `docker compose logs --tail=100 mlflow` |
| Модель или champion не найдены | Реальные имя модели, версии и alias в том же Registry |
| Приложение не стартует | `docker compose logs --tail=100 app`; доступность MLflow и наличие совместимой модели |
| После переноса alias API показывает старую версию | До restart это ожидаемо; после restart проверь успешность старта и адрес API |
| В Registry нет ожидаемого run | `MLFLOW_TRACKING_URI` в терминале, из которого выполнялось обучение |
| В контейнере не работает localhost:5000 | Для API в Docker нужен `http://mlflow:5000` |
| POST возвращает 422 | Нужен JSON с непустой строкой `text` длиной до 50000 символов |

Не используй `docker compose down -v` как способ обычного перезапуска: удаление volumes может уничтожить сохранённые данные MLflow и модели.

## 9. Репетиция целиком

Выполни последовательность без изменения исходников:

1. Покажи работающий `POST /process` и назови `model_version`.
2. Покажи ту же версию у alias `champion` в Registry.
3. Покажи вторую зарегистрированную совместимую версию.
4. Перенеси `champion` на неё.
5. Повтори запрос до restart и объясни старый номер.
6. Перезапусти `app` и дождись успешного старта.
7. Повтори запрос и покажи новый номер версии.
8. Перейди от версии в Registry к исходному run и его результатам.
9. При необходимости верни alias на исходную версию и перезапусти приложение.

Короткий рассказ, который можно адаптировать под фактическую демонстрацию:

> Приложение получает текст через POST /process и использует Pipeline, загруженный при старте. Ответ содержит точную версию модели. Выбор версии управляется alias champion в MLflow Registry. Я переназначаю alias и перезапускаю приложение: оно загружает новую версию без изменения inference-кода. Через Registry можно найти исходный run и проверить параметры, данные и метрики этой модели.
