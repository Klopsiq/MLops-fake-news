# Данные: WELFake

Источник: [Zenodo, запись 4561253, версия 0.1](https://zenodo.org/records/4561253). [Исходный CSV](https://zenodo.org/records/4561253/files/WELFake_Dataset.csv), около 245 МБ. Авторы: Pawan Kumar Verma, Prateek Agrawal, Radu Prodan; [статья](https://doi.org/10.1109/TCSS.2021.3068519).

В карточке описан англоязычный корпус новостей из нескольких источников. В доступном представлении карточки не удалось установить значение лицензии; лицензия проекта не распространяется автоматически на этот корпус. Исходник и подготовленные CSV не добавляются в Git.

## Важное несоответствие меток

На странице Zenodo написано `0 = fake`, `1 = real`. Но в CSV метка `0` встречается 35028 раз, `1` — 37106 раз: это соответственно числа real и fake из описания авторов. Из текстов с `(Reuters)` в начале 21115 имеют метку `0`, а 2 — метку `1`. Например, новость с заголовком `May Brexit offer would hurt, cost EU citizens - EU parliament` имеет метку `0`. Эти наблюдения поддерживают обратную интерпретацию меток. Полный [аудит](label-audit.json) и его ограничения сохранены в репозитории.

Для этой реализации принято **исходная метка 1 = fake, 0 = real**. Это интерпретация разметки корпуса по его содержимому и составу, а не независимая проверка истинности всех новостей. Противоречие с текстом карточки не скрыто. CLI специально требует `--fake-label`: преобразование не выбирается молча.

```bash
uv run --locked --all-groups python -m ml.data --download --fake-label 1
```

Скачивание проверяет MD5 `73c9675a4b3d09f86a6933d0b8d7d908`, опубликованный Zenodo. Рядом с CSV сохраняются URL, время проверки в UTC и SHA-256. Уже существующий файл не перезаписывается. При несовпадении MD5 работа останавливается.

## Что делает подготовка

Смотри код [ml/data.py](../ml/data.py). Последовательность фиксирована:

1. Прочитать исходник; `row_id` — позиция записи в прочитанном CSV.
2. Удалить пустые/пробельные тела новостей и невалидные метки.
3. Для поиска повторов применить casefold и схлопывание пробелов. Сам вход модели хранится с исходным регистром, обрезаются только пробелы по краям.
4. Удалить все записи с конфликтующими метками одинакового нормализованного текста. Остальные точные повторы свести к одной записи.
5. Разбить на train/validation/test = 70/15/15, со стратификацией и seed=42. Сохранить CSV и manifest с SHA-256, количеством строк и правилами подготовки.

Счётчики удаления последовательные: каждая удалённая строка учитывается один раз. Перепечатки с изменёнными словами автоматически не выявляются. В модель идёт только `text`; заголовок, имя источника и исходный серийный столбец не подаются отдельными признаками.

`data/raw/` и `data/processed/` сохраняются локально и исключены из Git и Docker build context. Dataset Tracking сохраняет метаданные, а не резервную копию этих файлов. Для воспроизведения нужны исходный CSV и та же версия подготовки.

Для быстрой технической проверки:

```bash
uv run --locked --all-groups python -m ml.data \
  --fake-label 1 --sample-size 1000 --output-dir data/processed-smoke
uv run --locked --all-groups python -m ml.train \
  --variant baseline --data-dir data/processed-smoke
```

Smoke runs имеют тег `purpose=smoke`. Их результаты нельзя ставить в одну таблицу с полным корпусом без явной отметки. Test используется только после выбора модели по validation.
